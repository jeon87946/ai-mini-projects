## 1. 검색기 구현 및 임베딩 확인 (CP-02~CP-06, CP-08)

| 검색 방식 | 사용 모델·표현 방식 | 전체 문서 벡터 Shape |
|---       |---               |---                 |
| TF-IDF | 문자 2~3-gram, `max_features=30000` | 200, 30000 |
| BERT | `klue/bert-base` + Masked Mean Pooling | 200, 768 |
| Sentence-BERT | `snunlp/KR-SBERT-V40K-klueNLI-augSTS` | 200, 768 |

- **BERT Encoder 출력 / Attention Mask / Pooling 결과 Shape (CP-03~04의 질문 2개):** (2, 19, 768) / (2, 19) / (2, 768)
- **BERT와 Sentence-BERT의 최대 입력 길이:** 256토큰
- **Padding을 평균 계산에서 제외하는 이유:** attention_mask=0이면 토큰에 어떠한 값이 들어있어도 0이 되기 때문에 제외하여야 한다.
- **BERT와 Sentence-BERT 문서 벡터를 혼합하지 않는 이유:** 두 모델은 학습 방식과 벡터가 나타내는 의미가 다르기 때문이다. 두 벡터를 합치면 의미가 왜곡될 수 있어 각각 독립적으로 성능을 비교하여야 한다.
- **Pooling·코사인 유사도·검색 결과 검증 셀 실행 결과:** 검증 셀 실행 정상

## 2. 검색 평가 기준 (CP-07)

- **평가에 사용하는 검색 결과:** Top-5 문서
- **질문별 지정된 정답 문서 수:** 1개
- **Hit@1이 평가하는 내용:** 가장 첫번째 답이 정답인지 확인한다
- **Recall@3이 평가하는 내용:** 검색결과가 3번째 안에 정답인지 확인한다.
- **MRR@5가 평가하는 내용:** 상위 5개 안에서 정답이 몇번째에 나왔는지 확인한다.
- **검색 지표 단위 테스트 결과:** 통과

## 3. 세 검색 방식의 성능 비교 (CP-07~CP-08)

`comparison_df`의 Validation 결과를 기록합니다.

| 검색 방식 | Hit@1 | Recall@3 | MRR@5 |
|---|---:|---:|---:|
| TF-IDF | 0.883 | 0.966 | 0.916 |
| BERT | 0.666 | 0.85 | 0.754 |
| Sentence-BERT | 0.766 | 0.883 | 0.820 |

**분석:** 지표별 성능 차이와 예상과 달랐던 결과가 있다면 그 가능 원인을 작성합니다. 
BERT와 SBERT 가 문맥과 의미적 유사도를 비교하여 학습하는 모델로 더 성능이 높을 줄 알았으나 이번 미니 프로젝트에서는 TF-IDF의 성능이 더 높게 나왔다. 원인은 데이터에 포함된 문서와 질문에서 겹치는 구간이 낮더라도 다른 문서보다 질문과 더 많이 일치한다면 정답을 찾을 수 있다. 이로 인하여 모델의 성능도 중요하지만 다른 문서와의 구분도 중요하다는 걸 알 수 있다.

## 4. 검색 오류 분석 및 가설 검증 (CP-09)

`error_cases`의 대표 분석 질문 5개를 기록합니다. 질문과 지정된 정답 문단, 실제 검색 문단의 본문을 비교하여 검색 결과의 차이와 원인 후보를 작성합니다. 정답이 Top-5에 없으면 순위를 '없음'으로 표시하세요. 실패 질문이 5개보다 적다면 실제 실패 건수와 나머지 성공 사례를 구분합니다.

| 질문 ID | 정답 문서 ID | TF-IDF 정답 순위 | BERT 정답 순위 | SBERT 정답 순위 | 겹침 비율 | 관찰한 결과 및 원인 후보 |
|---|---|---:|---:|---:|---:|---|
|   QV047 | D048	검색 실패	검색 실패	  4위       0.333
    QV020	D138	검색 실패	검색 실패	검색 실패    0.428
    QV046	D080	1위	        3위	        2위       0.166
    QV055	D034	1위	        4위	        3위         5
    QV033	D152	1위	        2위	       검색 실패   0.363

- **대표 실패 질문의 겹침 비율과 전체 Validation 평균의 차이:** 
대표 실패 질문 5개의 평균 겹침 비율은 약 0.36으로, 전체 Validation 질문의 평균 겹침 비율인 약 0.474보다 약 0.114 낮았다. 이를 통해 대표 실패 질문은 전체 질문보다 질문과 정답 문서 사이의 단어 표현이 덜 일치하는 경향이 있음을 확인했다.
- **겹침 비율이 낮은 대표 질문에서 상대적으로 잘 검색한 방식(관찰 가능한 범위):**
QV046은 겹침 비율이 약 0.167로 낮았지만, TF-IDF가 정답 문서를 1위로 검색해 가장 좋은 결과를 보였다. 따라서 겹침 비율이 낮더라도 핵심 키워드가 일치하면 TF-IDF가 좋은 검색 성능을 보일 수 있음을 확인했다.

**가설 검증:** `02_nlp_data_analysis.md`의 4절에서 세운 두 가설이 실제 결과와 일치했는지, 검색 순위와 문서 내용에 근거하여 작성합니다.
TF-IDF는 단어의 표면적인 일치 여부를 중심으로 검색하기 때문에 단어 겹침이 높은 질문에서 유리할 것으로 예상했다. BERT는 문맥과 의미를 파악하므로 표현이 다르더라도 의미가 유사한 문서를 찾는 데 장점이 있을 것으로 예상했다. 하지만 실제 결과에서는 겹침 비율이 낮은 질문에서도 TF-IDF가 정답을 1위로 검색하는 경우가 있었으며, BERT도 일부 질문에서 정답을 찾지 못했다. 따라서 예상한 모델별 장단점이 모든 질문에서 동일하게 나타나지는 않았다.

## 5. 최종 검색기 및 Test 평가 (CP-10)

- **Test 평가 전에 확정한 검색 방식(`SELECTED_METHOD`):** TF-IDF
- **직접 입력한 새로운 질문:** 지능형 교통시스템 관련 문서
- **`search_docs()`의 Top-3 문서 ID와 검색 결과에서 관찰한 점:** 
'지능형', '교통시스템'과 같은 핵심 단어가 문서의 표현과 정확하게 일치하여 관련성이 높은 문서가 상위 3개에 검색되었다. 이를 통해 질문과 문서 간 주요 키워드가 일치할수록 TF-IDF 검색에서 유리하게 작용할 수 있음을 확인했다.

동일한 검색 방식에서 `final_compare`의 결과를 기록합니다.

| 데이터 | 질문 수 | Hit@1 | Recall@3 | MRR@5 |
|---    |---:    |---:   |---:      |---:   |
| Validation | 60 | 0.883 | 0.966 | 0.916 |
| 보류 Test | 20 | 0.800 | 0.800 | 0.812 |

**해석:** Validation과 Test의 지표 차이를 실제 수치로 비교하고, Test에서 실패한 질문의 특징과 예상 원인을 작성합니다.  
인물과 같은 구체적인 사실을 묻는 질문과 단순한 오타나 문맥을 파악해야 되는 질문('ㅋ')에서 어려움이 있었을 것으로 예상된다. Tf-IDF는 문맥과의 관계보다는 단어의 일치 여부를 중심으로 검색하기 때문이다.
