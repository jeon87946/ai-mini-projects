## 2. 데이터 분할 및 누수 확인 (CP-02)

- **Train:** 2011-01-01 ~ 2012-05-25 / 12139건 / `cnt` 평균 159.72
- **Validation:** 2012-05-26 ~ 2012-09-11 / 2616건 / `cnt` 평균 281.04
- **Test:** 2012-09-12 ~ 2012-12-31 / 2624건 / `cnt` 평균 235
- **시간 순서로 분할한 이유:실제 대여 시간과 비슷하게 모델을 학습시키기 위해서이다.
- **`casual + registered == cnt` 확인 결과:** 전체 대여량 = 회원 대여량 + 비회원 대여량
- **누수 가능성이 있어 제외한 특성과 이유:** casual, registered을 합치면  cnt(대여량)이 나오므로 누수 가능성이 있는 특성을 제외하고 학습한다.

**분석:** 세 집합의 `cnt` 평균이 서로 다르다면, 그 차이가 이후 모델 평가에 어떤 영향을 줄지 1~2문장으로 작성합니다. cnt 평균이 다르면 대여량 분포의 차이가 있는 것으로 서로 다른 대여 패턴을 가진다.(예측 오차가 커진다)

## 3. 상관관계 및 입력 특성 분석 (CP-02)

- **`temp`와 `cnt`의 상관관계:** temp(기온)이 높을수록 대여량이 높아진다.(양의 상관관계)
- **`hum`과 `cnt`의 상관관계:** 습도가 높아지면 cnt는 낮이진다(음의 상관관계)
- **`windspeed`와 `cnt`의 상관관계:** 양의 상관관계
- **`temp`와 `atemp`의 상관관계:** 양의 상관관계
- **사용한 특성 목록(`FEATURES`):** temp(기온), atemp(체감온도), hum(습도), windspeed(풍속)에 따라서 대여량이 달라지는 것을 알 수 있다.

**분석:** 상관관계에서 알게 된 점과 상관계수만으로 특성을 결정할 수 없는 이유를 간단히 작성합니다.  
기온과 체감온도, 습도와 풍속 등에 따라서 대여량이 변화한다.

## 4. 특성공학 및 전처리 (CP-03)

- **생성한 특성:** `is_commute_hour`
- **특성 생성 조건:** 시간과 휴일 여부
- **범주형 특성 처리:** one-hot 인코딩으로 변환
- **수치형 특성 처리:** StandardScaler로 변환
- **이진 특성 처리:** 0, 1로 구분하므로 그대로 사용
- **Train 전처리 전후 Shape:** 12 → 58
- **Validation에 적용한 변환 기준:** transform
