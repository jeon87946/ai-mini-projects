## 2. 계층화 데이터 분할 (CP-02)

- **Train:** 8630건 / 구매 비율 15.48%
- **Validation:** 1850건 / 구매 비율 15.48%
- **Test:** 1850건 / 구매 비율 15.48%
- **`stratify`를 적용한 이유:** 원래 비율을 유지하고 데이터셋에 나눠주어 클래스 불균형을 방지한다.
- **1일차 회귀의 날짜 순서 분할과 다른 이유:** 이번 프로젝트는 특정 날짜 이후의 데이터를 예측하는 것이 아닌 구매 여부를 분류하는 것이 목적으로 시간적 순서를 유지할 필요가 없어 무작위로 분할하여도 된다.

**분석:** Train·Validation·Test의 구매 비율이 유사한지 확인하고 의미를 1~2문장으로 작성합니다. 원본 데이터의 구매와 미구매 비율이 각 데이터셋에도 비슷하게 들어가도록 stratify을 사용하여 나누었기에 편향을 줄일 수 있다.

## 4. 데이터 전처리 및 PyTorch 입력 준비 (CP-03)

- **범주형 특성(One-Hot 인코딩):** 0과 1로 구성한 여러개의 열로 변환하여 범주별 차이를 알 수 있게 학습시킨다.
- **수치형 특성(표준화):** 값의 범위를 0~1로 조정하여 특성 간의 값의 차이를 주었다.
- **이진 특성(변환 없이 사용):** 이미 0과 1로 표현되어 별도의 과정없이 사용하였다.
- **숫자로 표현된 코드값(`OperatingSystems`, `Browser` 등)을 범주형으로 처리한 이유:숫자로 나타나지만 순서와 같은 의미가 있는 것이 아니라 영향을 주지 않기 위해서 One-hot 인코딩으로 처리하였다.
- **`handle_unknown="ignore"`를 설정한 이유:** 새로운 범주형 데이터가 나와도 오류를 발생시키지 않고 0으로 처리하기 위해서이다.
- **Train 전처리 전후 Shape:** 17 → 73
- **Validation에 적용한 변환 기준:** Train 데이터로 전처리를 학습하고 동일한 기준을(transform) 적용한다.
- **PyTorch 입력·타깃 Tensor의 자료형 및 Shape:** (8630,73) (8630)
- **`DataLoader` 배치 크기와 배치 수:** 256 / 34

**분석:** 신경망 입력을 `float32` Tensor로 준비하고 미니배치를 만드는 이유를 1~2문장으로 작성합니다.  
신경망의 가중치와 손실값을 소수까지 계산할 수 있도록 float32 Tensor로 변환하였다.
전체 데이터를 한번에 처리하지 않고 미니배치로 나누어 메모리 사용량을 줄이고 효율적으로 학습할 수 있게 하였다.
